# astrbot_plugin_agent_progress

在聊天会话中实时查看 Agent 执行进度的 AstrBot 插件。

## 背景

Agent 处理长任务时，用户通常只能等到最终结果才知道过程如何。本插件把执行过程中的关键节点
实时推送到触发任务的会话，使执行过程可见。

## 依赖

需要启用 AstrBot 的 trace 功能（`trace_enable = true`）。插件通过 AstrBot 内部的日志广播器
获取 trace 事件，未开启时不会收到任何事件。

## 工作原理

1. 订阅 AstrBot 内部的日志广播器。
2. 过滤出 `type` 为 `trace` 的事件，按 `span_id` 归并为一次任务。
3. 识别关键动作：`astr_agent_prepare`（任务开始）、`agent_tool_call`（调用工具）、
   `agent_tool_result`（工具返回）、`astr_agent_complete`（任务结束）。
4. 按事件性质决定是否值得打扰用户，值得才投递回原会话。
5. 插件不调用大模型，不产生模型开销。

## 播报规则

默认按事件性质播报，只报四类，其余时间保持静默：

- 阶段切换：工具先按用途归类（执行命令、读写文件、联网请求、其它），类别变了才报，
  同类工具连续调用不报。距上次播报不足 `phase_min_interval` 秒的切换也会被吞掉。
- 异常：工具返回错误时立刻报。
- 疑似卡住：超过 `stuck_timeout` 秒没有任何新事件时报一条。
- 结束：任务收尾补一条汇总，尽量附上答案摘要与 Token 用量。

旧的「按时间间隔刷进度」没有删掉，改成由 `enable_interval_report` 控制，默认关闭。
打开后按 `start_after` 与 `interval` 两条阈值限频，和事件性质播报并行生效。

## 配置

| 配置项 | 类型 | 默认值 | 说明 |
| --- | --- | --- | --- |
| `target_session` | string | 空 | 只播报这个会话（精确匹配），留空表示所有会话都播报 |
| `quiet_mode` | bool | `false` | 安静模式：只报异常、卡住和结束，不报阶段切换 |
| `phase_min_interval` | int | `5` | 阶段切换判定阈值，距上次播报切换不足该秒数则不重复报 |
| `stuck_timeout` | int | `120` | 超过该秒数没有任何新事件就报一条疑似卡住 |
| `show_result` | bool | `true` | 任务收尾时是否补一条汇总 |
| `enable_interval_report` | bool | `false` | 是否启用旧的按时间间隔刷进度 |
| `start_after` | int | `30` | 旧的时间刷：任务耗时超过该秒数才开始播报 |
| `interval` | int | `30` | 旧的时间刷：两条播报之间的最小间隔（秒） |

## 输出示例

```
阶段：正在「联网请求」
异常：执行命令 返回错误
卡住：已经 120 秒没有新动静
完成：一共 18 步，用时 3 分 05 秒，Token 用量 1234
```

## 安装

将本插件目录放入 AstrBot 的 `data/plugins/`，然后在管理面板中重载插件。

## 注意事项

- 仅覆盖 AstrBot 自身的 Agent 任务，不监控外部进程。
- 工具归类表写死在代码里，未列出的工具一律归入「其它」。
- 卡住判定看的是整个任务有没有新事件，不看单个工具跑了多久，所以长时间单工具运行
  和真正卡住区分不开。
- 收尾汇总有门控，过程中一条都没播过的话，结束也不会单独发一条。
- 消息只回发到触发任务的会话，不支持指定其他目标。
- 关闭方式：停用插件，或打开 `quiet_mode` 再调大 `stuck_timeout`。
- trace 事件包含会话标识与消息摘要，属于敏感信息，请勿把事件流外发。

## 兼容性

支持 AstrBot v4.x，已在 aiocqhttp 平台验证。
